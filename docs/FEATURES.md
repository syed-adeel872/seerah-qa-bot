## Core Features — Seerah Q&A Bot

A detailed breakdown of every feature implemented in the Seerah Q&A Bot, from multi-language support to strict safety guardrails.

## 1. Multi-Language Support

The bot supports three languages with automatic detection and mirroring.

### Supported Languages

| Language | Detection Method | Example Query |
|----------|-----------------|---------------|
| **English** | Default fallback | "What was the Prophet's clothing?" |
| **Urdu Script** | Arabic character detection (`[\u0600-\u06FF]`) | "نبی ﷺ کا لباس کیسا تھا؟" |
| **Roman Urdu** | 90+ marker dictionary (`huzoor`, `kya`, `hai`, etc.) | "Huzoor ka libas kaisa tha?" |

### Language Mirroring

The bot mirrors the user's language — if you ask in Roman Urdu, you get Roman Urdu back:

```
User:  "Huzoor ka libas kaisa tha?"     (Roman Urdu)
Bot:   "Nabi ﷺ ka libas bilkul saada    (Roman Urdu)
        aur hareem tha..."
```

```
User:  "نبی ﷺ کا لباس کیسا تھا؟"        (Urdu)
Bot:   "نبی ﷺ کا لباس بالکل سادہ اور     (Urdu)
        حریم تھا..."
```

### Transliteration Engine

**`web/src/lib/l10n/translit.ts`** (16 KB) — a comprehensive Urdu→Roman transliteration table:
- Handles aspirates, retroflexes, nasal forms (ں), yeh/wao variants
- Roman Urdu titles prefer the corpus's own `slug.romanUrdu` (e.g. `libas`)
- Body text is generated by `urduToRoman` for natural output

### Trilingual Conflation

**76 conflation groups** unify English + Urdu script + Roman Urdu for retrieval:

```
clothing = {
  clothing, clothes, cloth, dress, dressed, attire,
  libas, kapra, kapre, kapray, pehnawa, pehnaw, poshaak, poshak,
  لباس, کپڑا, کپڑے, پہنتے
}
```

A query in any language lands on the same group — BM25 across trilingual corpus works.

## 2. Source-Grounded Answers

Every answer is grounded in verified corpus entries with full citation chain.

### How It Works

1. **Retrieval:** BM25 + semantic search finds the most relevant corpus entries
2. **Grounding gates:** Coverage ≥ 50%, BM25 ≥ 8, semantic score ≥ 0.62
3. **Generation:** LLM synthesizes answer from retrieved passages ONLY
4. **Citation:** Every source is listed with title (EN + UR) and Hawala reference

### Citation Display

Each grounded answer shows:

**Source Chips** — clickable badges at the bottom of the response:
```
[1] The Prophet's Clothing    [2] daily habits    [3] character traits
```

**Hawala Modal** — clicking a chip opens a detailed modal:
- Source type badge (Shamail / Seerah Timeline)
- English title
- Urdu title (RTL)
- Hawala / Reference box with hadith numbers and source names
- Category display

### Zero-Hallucination Guarantee

- Every statement traces back to a specific corpus entry
- No external knowledge is ever added
- If the corpus doesn't contain the answer, the bot says so (out-of-corpus)

## 5. Strict Guardrails System

### Three-Layer Defense

| Layer | Location | Timing | What It Catches |
|-------|----------|--------|-----------------|
| **Layer 1** | `blockers.ts` | Pre-retrieval | Exact keyword matches (fatwa, halal, qaza, etc.) |
| **Layer 2** | `answer.ts` | Post-LLM | LLM-generated refusals that slipped past Layer 1 |
| **Layer 3** | `chat-client.tsx` | Rendering | Any non-"answered" status hides citations |

### Fatwa Prevention

**30+ deterministic regex patterns** across 3 languages:

| Language | Examples |
|----------|----------|
| English | `fatwa`, `halal`, `haram`, `qaza`, `namaz timing`, `roza`, `zakat`, `nikah`, `talaq`, `wudu`, `ghusl` |
| Urdu script | `فتوی`, `حلال`, `حرام`, `قضا`, `نماز کا وقت`, `روزہ`, `زکوٰة`, `نکاح`, `طلاق`, `وضو`, `غسل` |
| Roman Urdu | `riwa`, `sud`, `jaiz`, `qaza`, `namaz`, `roza`, `zakat`, `nikah`, `talaq`, `wuzu`, `ghusl` |

When matched, the bot immediately returns a refusal — no retrieval, no generation.

### Scholar Redirect

For fatwa queries, the bot shows:

```
┌─────────────────────────────────────────────────────────┐
│ ⚠ This is a religious ruling (Shari'i masla).           │
│                                                         │
│ [Consult a qualified Islamic scholar (Aalim/Mufti)]     │
└─────────────────────────────────────────────────────────┘
```

- Refusal text in all 3 languages
- Clickable mailto link for scholar consultation
- No citations displayed

### Post-LLM Refusal Detection

**26 regex patterns** detect when the LLM generated a refusal:

```typescript
// English
/shari['']?\s?i\s?masla/i
/religious ruling/i
/consult\s+a\s+qualified\s+(scholar|aalim|mufti)/i

// Roman Urdu
/daaira[-\s]?e[-\s]?kaam\s+mein\s+nahi/i
/mustanad\s+aalim/i

// Urdu script
/(\u0634\u0631\u0639\u06CC\s+\u0641\u062A\u0648\u06CC\u06D2)/
/(\u0627\u0633\u062A\u0645\u0646\u062F\s+\u0639\u0627\u0644\u0645)/
```

When detected:
- `status` → `"blocked"`
- `citations` → `[]` (stripped)
- Frontend hides all citation UI

## 7. LLM-Powered Synthesis

### Three Language-Specific System Prompts

| Prompt | Language | Key Rules |
|--------|----------|-----------|
| `SYSTEM_PROMPT_EN` | English | 8 rules: fatwa redirect, out-of-corpus, semantic synthesis, laser-focused, ban on lazy fallbacks |
| `SYSTEM_PROMPT_ROMAN_UR` | Roman Urdu | 9 rules: includes mandatory context usage, flexible semantic synthesis |
| `SYSTEM_PROMPT_UR` | Urdu | 8 rules: post-LLM refusal enforcement, mandatory context usage |

### Semantic Synthesis Rule (Most Important)

> "Think like a researcher, not a search engine. DO NOT look for exact word matches. Read the full text of every passage. Extract ANY information that is thematically related to the user's question and weave it into a coherent, descriptive answer."

### Mandatory Context Usage Rule

> "If passages are provided to you in the 'Retrieved corpus passages' section, you are STRICTLY FORBIDDEN from saying 'I don't have details' or any absence message. You MUST synthesize a descriptive answer from those passages."

### Script Purity Rule (Roman Urdu)

**Rule 9 — "SCRIPT KI PAAKIZGI"** — Latin-only output enforcement.

Roman Urdu responses must contain only Latin characters. No Urdu/Arabic script characters are permitted in Roman Urdu output.

### Deterministic Fallback

If the LLM is unavailable or fails, the bot falls back to `generateDeterministicAnswer()`:
- Intro line per language
- Per source: `[n] Title`, trimmed narration, key points
- Closing line reiterating corpus grounding

## 9. Hybrid Retrieval Engine

### BM25 (Lexical)

- Per-field weighted: title × 4, keywords × 3, body × 2, slug × 1
- 76 trilingual conflation groups
- Standard BM25 with k1 = 1.5, b = 0.75

### Semantic (Vector)

- Gemini `gemini-embedding-001` (3072-dim)
- Precomputed embeddings (2.5 MB)
- Cosine similarity with LRU cache (256 entries)

### Hybrid Scoring

```
hybridScore = bm25Score + (semScore − 0.45) × 120
```

Strong semantic matches can overtake BM25 gaps of up to ~30 points.

## 11. Response Rendering Enhancements

### Bold Text Parsing

**`renderBoldText()`** — parses `**bold**` markdown into `<strong>` elements in assistant responses.

Allows the LLM to produce bold-formatted text that renders properly in the chat UI.

### Sanitize Roman Urdu Output

**`sanitizeRomanUrdu()`** — strips all non-ASCII characters from Roman Urdu LLM output to prevent cross-script corruption.

Ensures Roman Urdu responses remain purely Latin script, preventing accidental Urdu/Arabic characters from leaking into Roman Urdu output.

## 12. Race Condition Prevention

### AbortController for In-Flight Requests

When a user sends a new question while a previous request is still in flight, the app cancels the previous fetch using `AbortController`:

1. User sends question A → `fetch()` starts, `AbortController` stored
2. User sends question B before A completes → A is aborted via `abort()`
3. B proceeds normally

Prevents stale responses from rendering out of order.
